# World Model: Meta-Capability Underlying RCA / FI / Verifier

## Motivation

主线三元组 (FI / RCA / Verifier) 的任务在数学层面都隐含同一件事：**对系统行为的因果模型**。FI 要挑"能让 RCA 失手"的注入 —— 本质是 reason "我注入 X 会怎么传播"；RCA 要从观测推根因 —— 本质是反向 reason "什么注入会产生这种观测"；Verifier 要判定注入是否生效 —— 本质是 reason "正常情况下系统该长什么样，这次偏离多少"。三个任务都是同一个 world model 在**不同方向上的截面**。

**研究问题**：要不要把这件事**显式化**？训一个独立的 World Model agent，给 (system state, action) 预测 (system state')，并看 (a) 它能不能比商业 LLM baseline 更准；(b) 接到三元组里当 tool 用，能不能整体提升。这是**正交于主线**的研究线（和 Controller 同档位）—— 三元组本身可独立跑通，但有它可能更好。

## Setting

**输入**：注入前 state snapshot（metrics / traces / logs）+ 候选 action（故障注入描述）+ 服务拓扑。
**输出**：注入后 state 的多粒度预测 —— L1 受影响服务集合 / L2 指标方向 / L3 代码或 span 级 / 传播边（含时序）。
**评估对象**：
- (a) standalone WM 在 `propagation_edge_f1 / node_f1 / metric_direction_accuracy` 上 vs 商业 LLM baseline 的提升
- (b) 把 WM 当 tool 接给 FI / RCA / Verifier 后，三者各自主指标的提升幅度

详细 reward / 数据 / 消融维度已在 `.doc/designs/agent-roles-spec.md` §2.2 / §5.2 / Phase 2a 中定义；本 idea 文档主要是把那一摊东西**重新定位为正交研究线**而不是主线 agent。

## Modeling approach

两条路径，**probe 先做、standalone 看情况启动**：

1. **WM as probe**（先做，便宜）—— 不训独立 WM，而是给 RCA / FI / Verifier 设计探针任务（输入若干 state + action，输出预测的传播边/受影响节点），定量测它们**内部隐式的 world model 强度**。在主线训练前后各跑一次，看探针准确率随主线训练的变化曲线。
   - 如果三元组训练后内部 WM 能力显著上升 → standalone WM 的边际价值有限，可不做
   - 如果上升有限或停滞 → 证明显式 WM 必要，启动路径 2

2. **Standalone WM training** —— RCABench 历史注入的前后 snapshot 对作 SFT 数据，RL 阶段用自动 snapshot 比对算 reward (`node_f1 × w1 + direction_accuracy × w2 + edge_f1 × w3`，全自动无需 LLM judge）。训好后接给主线三元组当 tool。

## Differentiator

self-play / GASP / SGS 都假设 Solver 在做 black-box 推理，不显式建模"世界"。microservice 域天然有 RCABench 这种带前后 snapshot 的真实数据，能做出比文本游戏域扎实得多的 world model 训练。如果 probe + standalone 两条线都有结果，论文层面就是一个独立贡献：**首次定量回答"显式世界模型对 abductive multi-agent self-play 是否必要"**。
