# Data-Level Asymmetry Ladder for Decoupled Agents

## Motivation

Liu et al. (2026) 的核心论点：自演化系统会塌缩，根因不是 reward 不够好，而是 "Solver 进步了但 Proposer/Verifier 跟不上" 这种 strong-to-weak 同步缺失。论文里同步是隐式发生的（共享权重 + 同质任务下自动），但只要任务异质或训练目标分叉，权重共享自身就不一定够 —— 共享 init 之后分别 RL，参数会快速分歧。所以**同步机制要显式做出来**：**不靠权重通道，怎么保证 RCA 进步后 FI 和 Verifier 不会变成废物？**

如果不解决这件事，FI 会一直在过时的能力地图上挑题（Solver 已经掌握的故障被反复注入），Verifier 也会在过时的判定标准上打分。整个 self-play 闭环退化为"独立训练 4 个 agent"，丢掉论文的核心贡献。

## Setting

输入：所有 4 个 agent 的训练运行历史（包括各自 checkpoint、各自在共享 case 池上的表现、Verifier 的 judge 一致性）。
输出：
- 每个训练 round 后，三种自动同步动作之一：goalpost 集合刷新 / Verifier judge anchor 校准 / Replay buffer 重打分
- 一份"asymmetry 健康度"诊断 —— FI 是否还跑在 RCA 前面（不能太远，否则 noise；不能太近，否则塌缩）

评估对象：在 5+ rounds 的对抗循环里，本机制 vs "完全独立训练，互不通信" baseline，在 RCA F1 增长曲线和 FI 多样性两个指标上的差异。

## Modeling approach

用三个 data-level 机制把 strong-to-weak 同步显式化：

1. **Goalpost 漂移**（GASP 风格）：每 K 轮重新筛 H = "当前 RCA pass@N=0 的 case"。RCA 进步 → goalpost 自动变难 → FI 被迫升级
2. **Verifier judge anchor 校准**：用 Phase 1 硬编码 F1 作为 anchor，定期跑 Verifier 在 anchor case 上的判定一致性。一致性下降时触发 Verifier prompt 升级或重新蒸馏
3. **共享 replay buffer**：所有 RCA 失败 trace 进入一个共享池，FI 用作正样本、Verifier 用作 hard judge case、(可选) RCA 自己用作 negative example。这是论文 §3.3 主动信息获取的工程化实现 —— 数据自动反向流到所有需要它的角色

辅助监控指标 `asymmetry_gap`：FI 生成 case 的 RCA 平均 pass rate。`gap` 太低（< 0.2，FI 太强）说明 noise 化；太高（> 0.7，FI 太弱）说明塌缩化。落在 [0.2, 0.7] 是健康区间。

## Related work

- **self_play_evolves §3.1** (Liu et al.)：strong-to-weak 同步的理论基础；本 idea 是它在异质任务设定下的显式工程化
- **SPICE** (Liu et al., 2025a) / **SPELL** (Yang et al., 2025)：用外部数据池做 grounding，思路相近
- **现有 spec §3.1.1 Mock 解耦**：本 idea 是它的延续 —— Mock → real 替换路径如果没有 asymmetry ladder 会出现"替换后系统崩溃"

## Differentiator

论文里 strong-to-weak 是隐式的（依赖共享权重 + 同质任务自动同步），我们要把这件事**显式化为可监控、可干预的工程机制**，并证明它能 recover 论文的核心收益。这本身可能就是 paper-worthy 的贡献，因为现实中产研系统通常没法靠权重共享做隐式同步（任务异质 / 微调目标不同 / 部署架构限制）。
